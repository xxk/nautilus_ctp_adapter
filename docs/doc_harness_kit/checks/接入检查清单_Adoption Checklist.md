# 接入检查清单 / Adoption Checklist

**创建日期**：2026-03-27
**最后更新**：2026-03-27
**状态**：draft
**用途**：给一个新项目提供最短人工核对表，用于判断 `Doc Harness Kit` 是否真正接入，而不是只复制了文档目录。

---

## 一、使用方式

使用原则：

1. 每完成一轮接入动作，回看一次本表
2. 不要在未完成关键项时宣称“已接入”
3. 至少完成一轮真实试点后，才允许把状态改为“已接入”

---

## 二、最小接入清单

| 检查项 | 状态 | 说明 |
| --- | :---: | --- |
| 已建立仓库导航主入口 | ⬜ | 例如 `AGENTS.md` 或等价入口地图 |
| 已建立正式入口说明 | ⬜ | 能明确区分正式入口与兼容入口 |
| 已落地 change 模板 | ⬜ | `plan.md` / `acceptance.md` / `ai_constraints.md` 可复制 |
| 已明确 topic 与 change 分层 | ⬜ | topic 不承载单次执行细节 |
| 已建立至少一个验证入口 | ⬜ | 静态检查、测试、verify 任一可用 |
| 已明确临时产物输出目录 | ⬜ | 不允许根目录堆放临时文件 |
| 已完成一个真实试点 change | ⬜ | 不是只复制样板 |
| 已区分历史归档与当前正式口径 | ⬜ | 旧文档不会误导 AI |

---

## 三、升级清单

当项目准备从最小接入升级到更稳定的 harness engineering 治理时，再检查：

| 检查项 | 状态 | 说明 |
| --- | :---: | --- |
| 已建立最小守卫集合 | ⬜ | 见 `最小守卫规范_Minimal Guardrails.md` |
| 已建立任务类型到验证入口映射 | ⬜ | 见 `任务类型到验证入口速查表_Task Verification Matrix.md` |
| 已具备 topic 样板 | ⬜ | 长期主题可复用 |
| 已具备 archive 样板 | ⬜ | 历史文档有稳定归档方式 |
| 已形成命名迁移规则 | ⬜ | 展示名与证据锚点分离时有规范 |

---

## 四、通过标准

### 可称为“最小已接入”

满足以下全部条件：

1. 最小接入清单全部完成
2. 至少完成一个真实试点 change
3. 人工可以不依赖额外口头说明，判断当前正式入口、当前正式模板与当前验证方式

### 可称为“稳定可复用”

除上面外，还需满足：

1. 升级清单至少完成 4 项
2. 新成员或 AI 可以依靠仓库文档完成第一次闭环
3. 历史文档不会与当前正式口径打架
