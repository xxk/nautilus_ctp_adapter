# 示例变更包 / Example Change Bundle

**创建日期**：2026-03-27
**最后更新**：2026-03-27
**状态**：draft
**用途**：展示一个新项目第一次接入文档闭环执行套件时，可直接复制并改写的 `change bundle` 最小样板。

---

## 一、这份示例怎么用

这不是当前仓库的正式 change，也不是要直接在本仓执行的任务。

它的作用是给另一个项目一个可改写的起点：

1. 复制本目录下的 `plan.md`、`acceptance.md`、`ai_constraints.md`
2. 替换 `change-id`、`topic-id`、目录边界、验证命令、长期归宿
3. 再按目标项目的真实任务继续填写

---

## 二、为什么这个示例选择“统一运行入口”

因为这是大多数项目都会遇到的中风险问题：

1. 有多个历史入口
2. AI 容易改错落点
3. 验收信号相对清晰
4. 不依赖真实远端环境也能先跑本地闭环

所以它适合作为跨项目接入时的第一个试点 change。

---

## 三、复制后必须替换的内容

1. `project-entry` 这一类示例 `topic-id`
2. 示例中的目录路径与正式入口名称
3. 示例中的验证命令
4. 示例中的长期文档路径
5. 示例中的风险与非目标

---

## 四、配套文件

1. `plan.md`：展示一个真实可执行的计划写法
2. `acceptance.md`：展示一个真实可验收的场景板写法
3. `ai_constraints.md`：展示 AI 在这个 change 上如何执行
