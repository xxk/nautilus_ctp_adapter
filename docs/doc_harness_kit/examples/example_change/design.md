# 统一运行入口 / Unified Run Entrypoint 设计

> 这是跨项目示例文件，用来展示什么时候需要在三件套之外再补一份 `design.md`。

**状态**：待评审
**日期**：2026-03-27
**范围**：`scripts/`、导航文档、兼容入口说明
**关联 plan**：./plan.md

## 一、现状

当前项目存在多个可执行入口：

1. 一个新入口已经被大多数开发者使用。
2. 两个历史入口仍然保留在文档或脚本目录中。
3. AI 在不看导航的情况下，很容易继续修改到历史入口上。

## 二、正式入口与实现落点

1. 正式入口应落在 `scripts/run.py` 或目标项目当前唯一主命令位置。
2. 历史入口脚本只保留弃用提示、转发行为或显式失败说明，不再承载真实主逻辑。
3. 长期口径应沉淀到入口治理文档与 docs 首页导航。

## 三、设计方案

1. 先用一份长期文档冻结“唯一正式入口 + 兼容入口”的口径。
2. 再把正式实现收口到唯一入口文件。
3. 最后把历史入口改成兼容壳，并更新导航文档回链。

## 四、接口与输入输出

1. 正式入口应支持 `--help`，并输出项目当前唯一正式命令说明。
2. 兼容入口若继续存在，其输出必须明确写出“请使用哪个正式入口”。

## 五、AI 实现约束

1. 不得新增第二个“临时正式入口”作为过渡。
2. 不得把真实主逻辑继续留在兼容壳里，只在文档里假装已收口。
3. 正式入口不明确时，应先补文档，不要先写代码赌方向。

## 六、备选方案

备选方案：保留多个入口，只在 docs 中声明推荐顺序。

不选原因：

1. 这不能真正消除 AI 改错落点的问题。
2. 文档和代码容易继续漂移。

## 七、风险与影响面

1. 兼容入口改成显式弃用后，旧脚本调用方可能需要一次性迁移。
2. 若导航没有同步更新，用户仍可能从 docs 首页进入旧入口。

## 八、发布回滚与退出策略

1. 若正式入口收口后发现调用方尚未迁移，可临时把兼容入口改成纯转发。
2. 不允许回滚到“多个正式入口并列存在”的旧口径。

## 九、需要沉淀为长期规则的内容

1. 项目必须只有一个正式运行入口。
2. 兼容入口只能承担过渡或显式弃用提示。
