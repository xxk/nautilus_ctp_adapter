# 最小接入变更包 / Minimal Adoption Change Bundle

**创建日期**：2026-03-27
**最后更新**：2026-03-27
**状态**：draft
**用途**：给一个新项目提供“最小接入 5 步法”的真实执行包样板。复制到目标项目后，可直接作为第一笔 harness adoption child change 执行。

---

## 一、这份示例的定位

这不是当前仓库的正式 change，而是给别的项目一个可执行起点。

它要解决的问题不是“做一个业务功能”，而是：

1. 把 `Doc Harness Kit` 真正接到新项目里
2. 让 AI 找得到入口、模板和验证方式
3. 用这次 change 本身，完成第一个真实试点闭环

---

## 二、为什么这份 change 很重要

因为跨项目接入最容易停在半路：

1. 目录复制了，但没人知道怎么开始
2. 模板存在了，但没有正式落点
3. 文档写了，但验证命令还是假的

这份 change 的作用，就是把这些问题一次收掉。

---

## 三、最关键的结论

在目标项目里，**执行这份 change 本身，就可以作为“第一个真实试点 change”**。

前提是：

1. 它不是只创建空文件
2. 它真的回填了 evidence
3. 它真的验证了目标项目里的入口和命令

满足这三点后，它就不只是“接入准备”，而是接入完成本身。

---

## 四、复制后必须替换的内容

1. `change-id`
2. `topic-id`
3. 目标项目真实入口文档路径
4. 目标项目真实验证命令
5. 目标项目的 change/template 落点

---

## 五、配套文件

1. `plan.md`：定义最小接入 5 步该怎么拆任务
2. `acceptance.md`：定义怎样才算这 5 步真的做完
3. `ai_constraints.md`：约束 AI 先建入口、再建模板、再跑真实 change
4. `执行提示词_Execution Prompt.md`：给目标项目 AI 的可直接执行提示词
